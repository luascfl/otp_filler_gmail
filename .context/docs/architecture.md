## Architecture notes

## Runtime flow

1. `content.js` detects a visible OTP input.
2. It sends `START_POLLING` to `background.js` when no polling window is active.
3. The background runtime checks recent Gmail messages every three seconds for at most three minutes.
4. Message IDs in `seenMessageIds` prevent repeated injection of an old code.
5. A new code is sent to the active tab as `OTP_FOUND`.
6. `content.js` fills a single or split OTP field and dispatches Enter.
7. The popup provides account management, manual refresh, copy, and manual `FILL_CODE` fallback.

## Browser boundary

Shared runtime code stays in `background.js`, `content.js`, and the popup files. Browser differences remain in manifests and packaging:

| Contract | Chrome | Firefox |
| --- | --- | --- |
| Manifest | `manifest.json` | `manifest-firefox-mv3.json` |
| Background | `service_worker` | `scripts` |
| Stable identity | Chrome Web Store ID | `otp-filler-gmail@luascfl.github.io` |
| OAuth redirect | `<store-id>.chromiumapp.org` | SHA-1 of add-on ID under `extensions.allizom.org` |
| Distribution | Chrome Web Store | AMO unlisted signed XPI |

Firefox's redirect is generated by `browser.identity.getRedirectURL()` from the SHA-1 hash of the declared add-on ID. The current value is `https://b08a966e2cd56d5fdbe08615b80148bd4f58eaf3.extensions.allizom.org/`.

## State and data boundaries

- `chrome.storage.local`: account email and display name only.
- `chrome.storage.session`: short-lived access tokens and expiry metadata. Cleared with the browser session.
- In memory: Gmail responses, extracted codes, polling state, and seen message IDs.
- Google APIs: OAuth authorization, token revocation, user info, and Gmail read-only endpoints.
- No project server or third-party analytics endpoint exists.

## Security constraints

- OAuth scope is limited to `gmail.readonly`.
- The extension requests `<all_urls>` because automatic OTP field detection runs across websites.
- Firefox declares Mozilla data categories for authentication, personal communication, identifying information, website content, and website activity because those data classes are processed locally for the feature.
- OAuth client JSON files and AMO JWT credentials must remain outside commits and release archives.

## Build and release boundary

`npm run build:firefox` stages only runtime files into `dist/firefox` and rejects every `web-ext` warning. `npm run package:firefox` produces an unsigned inspection archive. `npm run sign:firefox` submits the staged source to AMO on the `unlisted` channel and returns the permanent-install XPI after Mozilla accepts it.
